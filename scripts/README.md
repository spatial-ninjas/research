# scripts

Utility scripts for building SSAL routing artifacts and evaluating routing-model outputs against the Helsinki routing-network artifacts versioned in this repository.

## Current scripts

### `build_ssal.py`

Builds a compact SSAL text artifact from the GeoPackage road-network input.

It currently:

- loads the configured edge and node layers from the GeoPackage
- converts the network into the repository SSAL text format using `research.ssal`
- writes the result to the configured output path

Default behavior:

- GeoPackage input: `data/raw/routing_networks/osm_southern_helsinki_slimmed_cropped.gpkg`
- edges layer: `slimmed_cropped_edges`
- nodes layer: `slimmed_cropped_nodes`
- output: `data/derived/ssal/ssal_osm_southern_helsinki_slimmed_cropped.txt`

The current default output format matches the historical SSAL artifact recipe:

- `length`
- `name`
- `oneway`
- `from_x`
- `from_y`
- `to_x`
- `to_y`

### `evaluate_history.py`

Thin CLI wrapper for offline route-history evaluation.

It currently:

- accepts either one dashboard history entry JSON or a bulk dashboard history export JSON
- delegates reusable evaluation work to `research.history_evaluation`
- loads/evaluates entries through the shared SSAL-native route evaluator
- writes JSON output to `--output` or prints JSON to stdout
- supports row-level results plus bulk summaries grouped by provider/model and by origin/destination route

The reusable helper module handles:

- loading one-entry and bulk history JSON files
- preserving dashboard/export metadata
- extracting explicit origin/destination route context
- loading a `NetworkBundle` from the configured GeoPackage
- building the evaluation graph from the SSAL text generated by the network loader
- calling `research.evaluation.evaluate_route_response`
- comparing candidate routes against Dijkstra ground truth over the SSAL-derived graph
- formatting and writing JSON output

## Setup

Create and activate a virtual environment first from the repository root.

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
```

For runtime-only usage:

```bash
python -m pip install -r requirements.txt
```

## Configuration

The evaluator supports CLI overrides and can also read local defaults from a repo-root `.env` file.

You can copy from `.env.example`.

Example `.env`:

```dotenv
GPKG_PATH=data/raw/routing_networks/osm_southern_helsinki_slimmed_cropped.gpkg
EDGES_LAYER=slimmed_cropped_edges
NODES_LAYER=slimmed_cropped_nodes
```

Required:

- none, when using the built-in local defaults

Optional:

- `GPKG_PATH`
- `EDGES_LAYER`
- `NODES_LAYER`

The default offline evaluator no longer requires:

```text
ORS_API_KEY
routingpy
OpenRouteService
```

## Running the SSAL builder

### Default run

```bash
python scripts/build_ssal.py
```

This uses the default historical SSAL recipe:

```bash
python scripts/build_ssal.py \
  --include-coords \
  --include-attrs length name oneway from_x from_y to_x to_y
```

### Include direction instead

```bash
python scripts/build_ssal.py \
  --include-direction \
  --include-attrs length name oneway dir
```

### Override main inputs

```bash
python scripts/build_ssal.py \
  --gpkg-path data/raw/routing_networks/osm_southern_helsinki_slimmed_cropped.gpkg \
  --edges-layer slimmed_cropped_edges \
  --nodes-layer slimmed_cropped_nodes \
  --output data/derived/ssal/custom_ssal.txt \
  --include-coords \
  --include-attrs length name oneway from_x from_y to_x to_y
```

### Show help

```bash
python scripts/build_ssal.py --help
```

## Running the evaluator

### Evaluate one history entry

```bash
python scripts/evaluate_history.py \
  --entry-json path/to/history_entry.json \
  --output result.json
```

### Evaluate a bulk history export

```bash
python scripts/evaluate_history.py \
  --history-json data/raw/llm_history_exports/llm_compare_history_2026-04-20.json \
  --output results/summaries/history_evaluation.json
```

### Override network inputs

```bash
python scripts/evaluate_history.py \
  --history-json data/raw/llm_history_exports/llm_compare_history_2026-04-20.json \
  --gpkg-path data/raw/routing_networks/osm_southern_helsinki_slimmed_cropped.gpkg \
  --edges-layer slimmed_cropped_edges \
  --nodes-layer slimmed_cropped_nodes \
  --output results/summaries/history_evaluation.json
```

### Print output to stdout

If `--output` is omitted, the evaluator prints JSON to stdout:

```bash
python scripts/evaluate_history.py \
  --entry-json path/to/history_entry.json
```

### Show help

```bash
python scripts/evaluate_history.py --help
```

## Expected history JSON shape

### One-entry input

The one-entry input should be one JSON object representing a dashboard route-history row.

The row should include explicit route metadata:

```json
{
  "id": 75,
  "provider": "OpenAI",
  "model": "gpt-5.4-mini",
  "finish_status": "completed",
  "max_output_tokens": 2048,
  "origin": "25291564",
  "destination": "25291567",
  "response_text": "{...model route JSON...}"
}
```

Fallback field names are supported:

```json
{
  "route_origin": "25291564",
  "route_destination": "25291567"
}
```

Rows without explicit route metadata are skipped with:

```json
{
  "status": "skipped",
  "reason": "missing_route_context"
}
```

The evaluator intentionally does not parse origin/destination from prompt text.

### Bulk input

The bulk input should be a JSON list of dashboard route-history rows:

```json
[
  {
    "id": 75,
    "provider": "OpenAI",
    "model": "gpt-5.4-mini",
    "origin": "25291564",
    "destination": "25291567",
    "response_text": "{...model route JSON...}"
  },
  {
    "id": 76,
    "provider": "Gemini",
    "model": "gemini-2.5-flash",
    "origin": "25291564",
    "destination": "25291567",
    "response_text": "{...model route JSON...}"
  }
]
```

## Expected model response schema

The primary expected model response schema is:

```json
{
  "origin": "25291564",
  "destination": "25291567",
  "total_length": 123.4,
  "route": [
    {"node": "25291564", "edge_name": "start"},
    {"node": "NEXT_NODE_ID", "edge_name": "STREET NAME"},
    {"node": "25291567", "edge_name": "STREET NAME"}
  ],
  "status": "success"
}
```

Important details:

- path validity is determined from `route[*].node`
- `edge_name` is preserved for debugging/display but is not used for graph validation
- `total_length` is treated as model-declared length, not trusted ground truth
- candidate length is recomputed from SSAL-derived graph edges
- ground truth is Dijkstra over the SSAL-derived graph

## Output shape

### One-entry output

One-entry output is wrapped under `result`:

```json
{
  "result": {
    "entry_id": 75,
    "provider": "OpenAI",
    "model": "gpt-5.4-mini",
    "origin": "25291564",
    "destination": "25291567",
    "ssal_hash": "...",
    "status": "evaluated",
    "valid_json": true,
    "valid_path": false,
    "candidate_path": ["25291564", "6497762829", "25291567"],
    "candidate_declared_length": 10.0,
    "candidate_computed_length": null,
    "ground_truth_path": ["25291564", "...", "25291567"],
    "ground_truth_length": 106.5
  }
}
```

### Bulk output

Bulk output contains both summary and row-level results:

```json
{
  "summary": {
    "total_entries": 2,
    "evaluated_entries": 2,
    "skipped_entries": 0,
    "skip_reasons": {},
    "valid_path_rate": 0.5,
    "average_relative_length_error": 2.949295774647886,
    "average_declared_length_relative_error": 0.6355206847360911,
    "per_model": {
      "OpenAI/gpt-5.4-mini": {
        "total_entries": 1,
        "evaluated_entries": 1,
        "skipped_entries": 0
      }
    },
    "per_route": {
      "25291564->25291567": {
        "total_entries": 2,
        "evaluated_entries": 2,
        "skipped_entries": 0
      }
    }
  },
  "results": []
}
```

Summary generation is pure aggregation over already-produced evaluation rows. It does not re-parse model responses, rebuild graphs, call Dijkstra, or call the evaluator again.

## Notes

- `build_ssal.py` is the CLI entry point for regenerating the versioned SSAL artifact.
- The reusable SSAL conversion logic lives in `research.ssal`.
- `scripts/evaluate_history.py` is intentionally a thin CLI wrapper.
- Reusable dashboard/export row adaptation, file wrappers, summaries, and JSON output helpers live in `research.history_evaluation`.
- `research.history_evaluation` uses `research.network_loader` to generate SSAL from the GeoPackage and builds the evaluation graph from that SSAL text.
- Route parsing, path validation, Dijkstra ground truth, and metric calculation live in `research.evaluation`.
- The default offline evaluator no longer requires ORS, routingpy, OpenRouteService, or `ORS_API_KEY`.
- Some history entries may be skipped if they do not include explicit origin/destination route metadata.
- The dashboard export flow should include top-level `origin` and `destination` fields for route-history rows.
